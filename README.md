# TRIP MAKER · טריפ מייקר 🧭

מתכנן טיולים בעברית — בונים מסלול יום-אחר-יום, מקבלים קוד שיתוף בן 6 ספרות, ושולחים לחברים.

## מה יש בפנים

- **עמוד בית** עם חיפוש יעדים / קוד טיול, רצועה מצומצמת של יעדים פופולריים מתחת לחיפוש — יעד בודד או שילוב של כמה מדינות ("הטיול הגדול במזרח", "דרום אמריקה"), שלחיצה עליו פותחת את האשף עם היעדים כבר בפנים (`public/js/popular.js`, רשימה אחת לדף הבית ולאשף) — וקרוסלת טיולים מומלצים
- **עמוד טיול** עם מסלול יומי, קישורי גוגל מפות לכל תחנה, מפה מוטמעת וכרטיס שיתוף בסגנון כרטיס עלייה למטוס
- **תכנון** — טיול שנוצר עם AI נפתח על שיחה, לא על מסלול מוכן: ה-AI שואל את שאלות ההבהרה בצ'אט, מציע לבנות **בבת אחת** (מסך טעינה ואז הטיול) או **שלב אחרי שלב** (מומלץ): קובעים יחד את האזורים, מבינים את הטיסות ויוצרים להן תחנות נסיעה, ואז 1–2 עוגנים ליום — וכל השאר מושלם אוטומטית בלחיצה. **טיול בכמה מדינות** לא מקבל את ההצעה "בבת אחת" בכלל: הוא מתחיל ישר שלב אחרי שלב, מדינה אחת בכל פעם, כדי לא להעמיס כמה מדינות על תור אחד של המודל (וגם `build_now` של המודל נזרק בקוד). ה-AI בונה ועורך את התחנות בעצמו דרך אותם ops, אותו אימות מקומות ואותו כותב של השינוי החכם. ליד שורת ההקלדה מתג **ידני** (כל שינוי מוצג ככרטיס לאישור) / **אוטומטי** (מתבצע מיד, עם ביטול). חלוקת האזורים שה-AI מציע מצוירת על לוח שנה בתוך הצ'אט, וצובעים ימים כדי לשנות. כשהטיול נראה מגובש ה-AI מציע פעם אחת להזמין חברים לתכנון (וואטסאפ / קישור). כל תור על המודל החזק — צ'אט הוא קול אחד, ושני מודלים נשמעו כשניים. השיחה וזיכרון התכנון (`trips.plan_state`: שלב, עובדות שהוסכמו, חלוקת האזורים) נשמרים בשרת (`trip_plan_messages`), כך שהמודל לא "שוכח" החלטה מלפני עשרים הודעות. מרגע השמירה הטאב הופך להמלצות. `routes/plan.js`; 20 הודעות ליום למשתמש
- **המלצות** — גם כאן מתג **ידני** / **אוטומטי** ליד שורת ההקלדה: ידני הוא הצ'אט כמו שהוא, ואוטומטי (למי שרשאי לערוך) מאפשר ל-AI להציע שינוי במסלול לאישור — רק כשמבקשים במפורש "תוסיף / תוריד / תזיז", אחרת ממליץ כרגיל. צ׳אט עם ה-AI על האזור, שעונה בכרטיסי המלצה (תמונה, קטגוריה, משך, עלות) עם ➕ שמכניס אותם למסלול דרך בוחר-יום בתצוגת חודש, או "תבחרו בשבילי". `POST /api/trips/code/:code/recs`: המודל החזק עונה, **כל מקום מאומת** מול Photon/Google ומה שלא אומת נזרק, תמונות מוויקיפדיה (חינם, בלי מפתח), 30 שאלות ליום למשתמש
- **מסמכים** — כרטיסי טיסה, דרכון, הזמנות וביטוח לכל טיול, מתויגים לתיקיות אוטומטית: מיד לפי שם הקובץ, ואז לפי **התוכן** — שכבת הטקסט של PDF (pdf.js), קבצי טקסט/HTML/EML/DOCX, ו-OCR לתמונות ולסריקות (ה-TextDetector של הדפדפן כשיש, אחרת tesseract.js ב-WASM — רק במכשיר שנראה מסוגל, על עותק מוקטן ובתקציב זמן; טלפון חלש או חיבור חסכוני נשארים עם התיוג לפי השם, או "אחר", והבחירה הידנית תמיד נשארת). הכול רץ בדפדפן: הקבצים והטקסט לא עולים לשרת — רק מנועי הזיהוי נטענים מ-jsDelivr בפעם הראשונה. נשמרים **רק במכשיר** (IndexedDB, לפי משתמש+טיול). הכללים ב-`public/js/doc-classify.js`, ובדיקתם: `node tools/docs-classify-check.js`
- **מכסות ה-AI** (`lib/quota.js`) — מונה יומי אחד לכל פיצ'ר (בניות, שינויים חכמים, שאלות המלצות, הודעות תכנון), נשמר ב-DB (`ai_usage`) ולא בזיכרון, כי השרת החינמי מתאתחל בכל deploy ונרדם אחרי רבע שעה. מנהלים לא מוגבלים. כשהמכסה נגמרת הצ'אט לא מציג שגיאה אלא כרטיס: אפשר להמשיך ידנית ומחר יש מכסה חדשה — ומי שמשתף את האפליקציה בוואטסאפ ושלושה חברים נרשמים דרך הקישור שלו (`/?ref=CODE`, `GET /api/me/referral`) מקבל **מכסה כפולה** לכל המונים, לתמיד
- **אשף תכנון** בשלושה צעדים — יוצר טיוטה ריקה ונוחת בטאב התכנון (`/trip/CODE#plan`)
- **חשבונות משתמשים** (JWT + bcrypt) ועמוד "הטיולים שלי"
- **WebMCP** — כלים בשם לסוכני AI, במקום ניחושים על ה-DOM (ראו למטה)

## סטאק

- Node.js + Express, PostgreSQL (Render)
- Frontend: HTML/CSS/JS ללא פריימוורק, RTL מלא, עיצוב זכוכית
- APIs חינמיים ללא מפתח: Open-Meteo (חיזוי מזג אוויר + Geocoding לאוטוקומפליט יעדים בעברית), OSM Overpass (מלונות באזור, עם קאש בצד השרת), Google Maps Embed

## WebMCP — ממשק לסוכני AI

האתר מצהיר על עצמו לסוכנים דרך [WebMCP](https://webmachinelearning.github.io/webmcp/): במקום שסוכן ינחש איפה
לוחצים, הדף מגיש לו כלים בשם, עם סכימת קלט ותוצאה מובנית.

הכלים נרשמים לכל מארח שהדפדפן חושף, לפי הסדר: `document.modelContext` (הטיוטה של W3C),
`navigator.modelContext` (Edge 147 / ה-origin trial של Chrome 149), ובכל מקרה גם `window.tripmakerTools` —
גשר משלנו. הגשר הוא זה שעובד היום בפועל: תמיכה נייטיבית עדיין דקה, ורוב הסוכנים שמגיעים לאתר עושים זאת
דרך דפדפן headless שבו הערוץ היחיד הוא הרצת JS.

```js
window.tripmakerTools.host              // 'document' | 'navigator' | null
window.tripmakerTools.list()            // כל הכלים: שם, תיאור, inputSchema, annotations
await window.tripmakerTools.call(name, input)
```

התוצאה תמיד באותו מבנה — `content` קריא לאדם ו-`structuredContent` לפרסור. כישלון חוזר כתוצאה עם
`isError: true` ולא כחריגה, כדי שסוכן יוכל לקרוא את הסיבה ולנסות מהלך אחר.

**בכל דף** (`webmcp-tools.js`): `tripmaker_whoami` · `tripmaker_search_trips` ·
`tripmaker_list_suggested_trips` · `tripmaker_get_trip` · `tripmaker_list_my_trips` ·
`tripmaker_search_destinations` · `tripmaker_create_trip` · `tripmaker_open`

**רק כשטיול פתוח** (נרשמים מ-`trip.js`): `tripmaker_current_trip` · `tripmaker_add_stop` ·
`tripmaker_update_stop` · `tripmaker_delete_stop`

כלי התחנות עוברים דרך `addItem`/`saveItem`/`deleteItem` של הדף עצמו, לא ישר ל-API — כך עריכה של סוכן
מתרנדרת בשתי התצוגות בדיוק כמו עריכה של אדם, במקום להשאיר על המסך מסלול שכבר לא קיים.

הערות אבטחה: כלי קריאה מסומנים `readOnlyHint`, וכל כלי שמחזיר תוכן שנוצר על ידי משתמשים אחרים מסומן גם
`untrustedContentHint`. הרשאות לא נעקפות — הכלים רוכבים על אותו JWT ואותן בדיקות הרשאה של ה-API, וסוכן
לא מתחבר בשם המשתמש. `/admin` לא טוען את הכלים בכוונה.

## הרצת מיגרציות

`node db/migrate.js` — עמודת destinations (ריבוי יעדים + קואורדינטות), אידמפוטנטי.

## הרצה מקומית

```bash
npm install
# צרו קובץ .env עם:
# DATABASE_URL=postgresql://...
node db/setup.js   # פעם אחת: סכימה + טיולים מומלצים
npm start          # http://localhost:3000
```

## משתני סביבה

| משתנה | תיאור |
|---|---|
| `DATABASE_URL` | כתובת חיבור ל-PostgreSQL. הסכימה, המיגרציות והטיולים המומלצים נוצרים לבד בעלייה (`lib/db-bootstrap.js`) — מסד נתונים חדש לא צריך שום צעד ידני |
| `IMPORT_FROM_DATABASE_URL` | חד-פעמי: כתובת מסד הנתונים **הישן** (חי). בעלייה הבאה השרת מעתיק ממנו את כל הטבלאות (משתמשים, טיולים, תחנות…) עם אותם מזהים — רק לתוך מסד שאין בו עדיין משתמשים, אחרת מדלג. מסירים אחרי הריצה |
| `DB_BACKUP_KEY` | סוד לפענוח גיבוי ה-escrow החודשי. כשהוא מוגדר, מסד ריק (או שיש בו רק טיולי הדגמה) משוחזר אוטומטית בעלייה מהגיבוי המוצפן ב-GitHub (`lib/db-restore.js`). בלעדיו אין שחזור — רק seed |
| `RESTORE_FROM_ESCROW` | `1` = לכפות שחזור מה-escrow **גם על טיולי הדגמה שכבר קיימים** (התאוששות חד-פעמית). מוחק ומשחזר; מסירים אחרי הריצה. בלי זה השחזור רץ רק על מסד ריק/דגמה |
| `RESTORE_SOURCE_URL` | אופציונלי — כתובת קובץ ה-escrow. ברירת מחדל: ה-raw של `ofir6868/tripi` בענף `db-rotation-backups` |
| `JWT_SECRET` | סוד לחתימת טוקנים |
| `PORT` | פורט (ברירת מחדל 3000) |
| `CANONICAL_ORIGIN` | אופציונלי — המקור היחיד שמותר להיכנס לאינדקס. ברירת מחדל `https://tripmaker.co.il` (מתוך `SITE` ב-`lib/seo.js`). כל בקשת GET לדף שמגיעה למארח או לסכימה אחרים מקבלת 301 לכאן |
| `GOOGLE_PLACES_API_KEY` | מפתח Google Places (New) — אוטוקומפליט של יעדים, וגם תמונות המקומות בכרטיסי ההמלצות. בלעדיו התמונות נופלות חזרה לוויקיפדיה |
| `AI_MODEL_PLAN` | אופציונלי — המודל של צ'אט התכנון. ברירת מחדל: `AI_MODEL_STRONG`, כי התורות שלו מכניסות מקומות אמיתיים ישר למסלול |
| `AI_QUOTA_PLAN` / `AI_QUOTA_RECS` / `AI_QUOTA_BUILD` / `AI_QUOTA_EDIT` | אופציונלי — מכסה יומית למשתמש לכל מונה (ברירות מחדל 20 / 30 / 20 / 3). `AI_QUOTA_PLAN=2` הוא הדרך לראות את כרטיס המכסה בלי שישים תורות אמיתיים |
| `PLACE_PHOTO_MONTHLY_LIMIT` | תקרת בקשות תמונה ל-Google בחודש (ברירת מחדל 900 — מתחת למכסת החינם של 1,000). מעבר לתקרה, תמונות מגיעות מוויקיפדיה. כל מקום נמשך פעם אחת ונשמר בקאש |
| `GOOGLE_CLIENT_ID` | OAuth 2.0 Client ID מ-Google Cloud |
| `GOOGLE_CLIENT_SECRET` | OAuth 2.0 Client Secret מ-Google Cloud |
| `GOOGLE_REDIRECT_URI` | אופציונלי — ברירת מחדל `{origin}/api/auth/google/callback` (בפרודקשן: `https://tripi-caw3.onrender.com/api/auth/google/callback`) |
| `HOTEL_CONTENT_PROVIDER` | ספק תוכן המלונות: `osm` (ברירת מחדל, ללא מפתח) או `liteapi` |
| `LITEAPI_KEY` | מפתח LiteAPI — בלעדיו המערכת נופלת חזרה ל-`osm` ולא נשברת |
| `HOTEL_GUEST_NATIONALITY` | לאום האורח לתמחור (ברירת מחדל `IL`) |

### התחברות עם Google

ב-Google Cloud → OAuth client (Web application):

- **Authorized JavaScript origins:** `https://tripi-caw3.onrender.com` (ו־`http://localhost:3000` לפיתוח)
- **Authorized redirect URIs:** `https://tripi-caw3.onrender.com/api/auth/google/callback` (ו־`http://localhost:3000/api/auth/google/callback`)

אחרי הגדרת המשתנים, הריצו `node db/migrate.js` פעם אחת (עמודת `google_sub` + סיסמה אופציונלית).

בדיקת הספק הפעיל: `node tools/hotel-content-probe.js` (או `node tools/hotel-content-probe.js liteapi`).
